01CONTEXT & CHALLENGE

많은 데이터를 보여주는 것만으로는 다음 행동이 정해지지 않아요.

데이터 위계와 운영 맥락

공간과 데이터

건물·층·설비의 데이터가 어느 공간에 속하는지 함께 읽혀야 해요.

확인과 대응

상태를 확인한 뒤 필요한 조치로 넘어갈 때 맥락이 끊기지 않아야 해요.

USER CONTEXT

특정 공간의 설비 상태를 확인하고 대응하는 상황

기능 이름보다 실제 공간을 따라 필요한 정보를 찾는 흐름을 먼저 봤어요.

DESIGN PERSPECTIVE
건물 → 층 → 설비의 관계를 탐색 구조로 옮기고, 확인 → 판단 → 실행을 연결했어요.

기존 설계 기록에 담긴 관점이에요. 별도의 사용자 조사 결과는 아직 확인되지 않았어요.

02INFORMATION ARCHITECTURE

기능 목록 대신, 실제 공간의 위계를 따라가요.

  1. 01

    건물

    전체 에너지 현황을 확인해요.

  2. 02

    층

    확인할 공간으로 범위를 좁혀요.

  3. 03

    설비

    상태를 확인하고 필요한 조치로 이어가요.

기존 설계 설명에서 정보의 관계와 이동 순서를 요약했어요.

03DESIGN DECISIONS

이렇게 판단하고, 설계했어요.

01

공간을 탐색의 기준으로

문제
에너지 데이터를 기능별로 나열하면 실제 위치와의 관계를 다시 해석해야 해요.
판단 기준
사용자가 알고 있는 공간 구조로 정보를 찾게 했어요.
설계
건물 → 층 → 설비 순서의 계층형 탐색을 설계했어요.
02

상태 확인과 조치의 연결

문제
상태 확인과 실행이 별도 화면으로 흩어지면 흐름이 끊겨요.
판단 기준
확인한 상태를 유지한 채 다음 행동으로 이어지는 것을 기준으로 삼았어요.
설계
상태 정보와 필요한 조치를 같은 맥락에서 확인하도록 인터페이스를 구성했어요.
04DESIGN SYSTEM

화면을 넘어, 일관된 기준으로.

반복되는 화면과 예외 상태를 같은 기준으로 다루기 위한 규칙이에요.

반복되는 UI의 기준

컬러·타이포그래피와 컴포넌트 기준을 묶어 화면 간 일관성을 맞췄어요.

조합 가능한 구조

Figma 슬롯을 활용해 여러 UI를 같은 패턴 안에서 조합하도록 구성했어요.

상태와 예외 전달

UI 상태·인터랙션·예외 케이스를 화면 주석에 연결해 협업 기준을 공유했어요.

05AI IN THE PROCESS

디자인 과정에서의 AI 활용 기록을 추가할 예정이에요.

내용 준비 중 · 실제 활용 내역 미확인

통합 관제 에이전트는 제품에 들어간 기능이에요. 디자이너가 작업에 AI를 활용한 기록과 구분해요.

PROCESS & COLLABORATION

설계 기준을 함께 읽을 수 있도록.

프로젝트에 남아 있는 설계·협업 자료예요.
