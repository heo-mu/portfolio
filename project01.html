Digital Twin ⁠·⁠ Energy Management

삼성 BEES공간을 따라 읽는 에너지 관리 플랫폼

건물⁠·⁠층⁠·⁠설비의 에너지 데이터를 디지털 트윈에 연결한 관리 플랫폼이에요. 기능별로 흩어진 데이터를 공간의 위계로 다시 묶어, 운영자가 위치와 상태를 먼저 읽고 바로 조치하도록 설계했어요.

01Context

기능별로 흩어진 에너지 데이터

기존 시스템은 에너지 데이터를 기능 단위로 나눠 보여줬어요. 그래서 수치를 볼 때마다 그 값이 어느 건물⁠·⁠층⁠·⁠설비의 것인지 다시 해석해야 했어요.

기존 시스템 구조

공간과 분리된 데이터

데이터가 기능 단위로 나뉘어 있어, 어느 공간의 값인지 함께 읽기 어려웠어요.

확인과 대응의 단절

상태를 확인하는 화면과 조치하는 화면이 나뉘면 확인한 맥락이 이어지지 않아요.

설계 관점

기능 이름을 익히게 하기보다, 운영자가 이미 알고 있는 실제 공간을 따라 정보를 찾게 하는 것이 먼저라고 봤어요.

02Information Architecture

공간 위계를 따르는 탐색 구조

기능 목록 대신 건물 → 층 → 설비의 위계를 탐색 기준으로 삼아, 기능 이름을 몰라도 원하는 설비까지 이동하게 했어요.

  1. 01

    건물

    전체 에너지 현황을 확인해요.

  2. 02

    층

    확인할 공간으로 범위를 좁혀요.

  3. 03

    설비

    상태를 확인하고 필요한 조치로 이어가요.

03Design Decisions

확인에서 조치까지 이어지는 운영 화면

상태를 확인한 화면에서 바로 판단하고 실행할 수 있도록, 흐름이 끊기는 지점을 줄였어요.

01

한 화면 안의 확인 → 판단 → 실행

문제
화면 전환이 많아질수록 상태 확인과 조치 사이의 흐름이 끊겨요.
판단
확인한 상태를 유지한 채 다음 행동으로 이어지는 것을 기준으로 삼았어요.
설계
상태 정보와 필요한 조치를 같은 화면에 두어, 확인 → 판단 → 실행이 한 흐름으로 이어지게 했어요.

02제품 기능 ⁠·⁠ AI 관제 에이전트

알림에서 조치로 이어지는 관제

문제
설비 상태와 이상 신호가 여러 화면과 수치로 나뉘면, 상황을 파악하고 대응하기까지 오래 걸려요.
판단
알림을 확인하는 데서 끝나지 않고, 필요한 행동까지 한 흐름으로 이어져야 한다고 봤어요.
설계
실시간 알림과 대화형 인터페이스를 묶어, 위험 징후와 필요한 조치⁠·⁠경로를 먼저 보여주는 통합 관제 에이전트를 설계했어요.

04Design System & Collaboration

컴포넌트와 Figma 주석으로 맞춘 구현 기준

컬러⁠·⁠타이포그래피 기준을 표준화하고, 구현에 필요한 상태와 예외는 Figma 안에서 바로 확인하게 했어요.

슬롯 기반 컴포넌트

Figma 슬롯으로 여러 UI를 하나의 패턴 안에서 조합해, 같은 구조를 반복해서 만들지 않게 했어요.

주석으로 전달한 구현 기준

UI 상태⁠·⁠인터랙션⁠·⁠예외 케이스를 주석에 함께 적어, 구현 기준을 화면에서 바로 확인하게 했어요.

05Key Screens

공간 단위로 이어지는 운영 화면

대시보드와 에너지 관리, 연돌, 화재⁠·⁠피난 시뮬레이션 화면이에요.

06Result

공간과 상태가 먼저 읽히는 운영 구조

기능별로 흩어져 있던 데이터와 운영 흐름을 이렇게 정리했어요.

  1. 01

    공간 단위 탐색

    기능별로 흩어진 데이터를 건물⁠·⁠층⁠·⁠설비 단위로 찾아요.

  2. 02

    한 흐름의 확인과 조치

    상태 확인 → 판단 → 실행이 한 화면에서 이어져요.

  3. 03

    반복을 줄인 협업 구조

    슬롯 컴포넌트와 주석으로 같은 구조의 반복 제작과 구현 해석 차이를 줄였어요.

이 프로젝트에서 보여준 역량

  • 데이터 위계 설계에너지 데이터를 공간 단위로 읽히게 정리했어요.
  • 운영 흐름 연결상태 확인과 다음 조치를 하나의 흐름으로 설계했어요.
  • 시스템과 개발 협업반복 패턴과 예외 기준을 컴포넌트와 주석으로 전달했어요.

다음 작업에 가져갈 기준

많은 지표를 한 화면에 담는 것보다, 어느 공간의 어떤 상태인지가 먼저 읽히는 구조가 운영 화면의 출발점이었어요. 확인과 조치를 같은 맥락에 두는 것을 운영 화면 설계의 기준으로 삼아요.
