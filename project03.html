01CONTEXT & CHALLENGE

분석된 내용을 믿기 전에, 직접 확인할 수 있어야 해요.

분석 결과의 검증과 다음 행동

인식 결과와 원문

OCR로 읽은 항목을 원문과 비교하고, 확인할 부분을 구분해야 해요.

다양한 사용 환경

문서 형식·비율·화면 크기가 달라도 점검 흐름이 이어져야 해요.

USER CONTEXT

근로계약서와 현장 사진을 올리고 결과를 검토하는 상황

사용자가 인식 결과를 직접 검토하고 다음 조치를 알 수 있는지가 중요했어요.

DESIGN PERSPECTIVE
자동 분석 결과 자체보다 원문과의 비교, 확인할 항목, 조치 안내의 연결을 먼저 설계했어요.

기존 설계 기록에 담긴 관점이에요. 별도의 사용자 조사 결과는 아직 확인되지 않았어요.

02INFORMATION ARCHITECTURE

입력 이후에도 사용자가 확인하는 단계를 남겨요.

  1. 01

    자료 입력

    근로계약서와 현장 사진을 올려요.

  2. 02

    원문 확인

    OCR 항목을 원문과 비교해요.

  3. 03

    결과 검토

    확인할 내용과 위험 요소를 읽어요.

  4. 04

    후속 행동

    점검과 조치 안내로 이어져요.

기존 설계 설명에서 정보의 관계와 이동 순서를 요약했어요.

03DESIGN DECISIONS

이렇게 판단하고, 설계했어요.

01

원문을 검토의 기준으로

문제
인식 결과만 보여주면 잘못 읽힌 항목을 확인하기 어려워요.
판단 기준
사용자가 결과를 직접 검증할 수 있어야 해요.
설계
원문과 OCR 결과를 함께 보여주고, 확인이 필요한 항목을 구분했어요.
02

예외도 같은 검토 경험으로

문제
긴 문서, 넓은 이미지, PDF와 확대 상태의 조건이 달랐어요.
판단 기준
파일 특성이 달라도 내용을 놓치지 않도록 동작 기준을 정했어요.
설계
세로 문서의 스크롤, 가로 이미지의 전체 보기, PDF 페이지와 확대 상태를 나눠 설계했어요.
03

익숙한 공공 서비스 구조

문제
연령과 디지털 숙련도가 다른 사용자가 함께 이용해요.
판단 기준
낯선 조작보다 익숙한 구조와 분명한 문장이 필요했어요.
설계
KRDS 기준을 바탕으로 입력 → 확인 → 조치의 흐름을 구성했어요.
04DESIGN SYSTEM

화면을 넘어, 일관된 기준으로.

반복되는 화면과 예외 상태를 같은 기준으로 다루기 위한 규칙이에요.

공공 서비스의 일관성

KRDS를 기준으로 정보 구조와 화면을 설계했어요.

파일별 확인 방식

이미지 비율·PDF·확대 상태별 동작을 문서화했어요.

모바일의 연속성

업로드부터 인식 결과 확인·분석·자율점검까지 이어지는 화면을 구성했어요.

05AI IN THE PROCESS

설명에 필요한 장면을 구체화하고, 생성 결과를 검토했어요.

01

작업의 출발점

실제 사진이 부족한 위험 상황과 작업 환경을 설명할 보조 이미지가 필요했어요.

02

AI가 도운 범위

ChatGPT로 장면과 위험 요소를 구체화하고, Firefly·나노바나나로 이미지를 생성했어요.

03

직접 내린 판단

설명할 상황과 위험 요소를 정하고, 생성 결과를 검토하며 프롬프트를 다듬었어요.

기존 ‘AI 이미지 생성’ 기록에 근거한 내용이에요. 실제 현장 사진과 생성 이미지를 구분하고, 생산성 수치는 기재하지 않았어요.
