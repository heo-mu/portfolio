01CONTEXT & CHALLENGE

제품이 들어가는 것과 편하게 사용할 수 있는 것은 달라요.

설치 조건을 이해하고 판단하는 흐름

크기와 사용 조건

본체 치수뿐 아니라 문 열림과 주변 공간까지 함께 봐야 해요.

숫자와 공간의 연결

제품 규격과 실제 공간을 따로 보면 설치 장면을 가늠하기 어려워요.

USER CONTEXT

냉장고를 고른 뒤 설치 공간을 확인하는 상황

선택한 제품을 놓치지 않고 공간 조건을 이어서 입력할 수 있어야 해요.

DESIGN PERSPECTIVE
기능을 더하기 전에 제품 선택 → 공간 설정 → 결과 확인의 순서를 먼저 정했어요.

기존 설계 기록에 담긴 관점이에요. 별도의 사용자 조사 결과는 아직 확인되지 않았어요.

02INFORMATION ARCHITECTURE

선택한 제품을 기준으로, 공간과 결과를 이어가요.

  1. 01

    제품 선택

    비교할 제품 규격을 정해요.

  2. 02

    공간 설정

    치수를 입력하고 3D에서 배치해요.

  3. 03

    설치 결과

    남는 공간과 확인할 조건을 함께 봐요.

기존 설계 설명에서 정보의 관계와 이동 순서를 요약했어요.

03DESIGN DECISIONS

이렇게 판단하고, 설계했어요.

01

앞선 선택을 가리지 않는 단계

문제
모달이 직전에 선택한 제품을 가리는 구조였어요.
판단 기준
제품 선택의 맥락을 다음 단계에서도 유지하는 것을 기준으로 삼았어요.
설계
제품 선택 → 공간 설정 → 3D Fit Checker로 단계를 연결했어요.
02

계산값보다 이해할 수 있는 상태

문제
여유 공간이 음수일 때 계산값이 그대로 노출됐어요.
판단 기준
계산에 필요한 값과 사용자가 읽을 설명은 다르게 다뤄야 해요.
설계
숫자만 보여주는 대신 설치 불가 상태와 확인할 조건으로 표현했어요.
03

표시 단위와 정확성의 균형

문제
공간을 읽는 단위와 판정에 필요한 정밀도가 달랐어요.
판단 기준
사용자가 공간을 가늠하기 쉬운 표기와 계산 정확성을 함께 지켜야 해요.
설계
화면은 cm로 보여주고, 내부 계산과 표시의 경계를 분리했어요.
04DESIGN SYSTEM

화면을 넘어, 일관된 기준으로.

반복되는 화면과 예외 상태를 같은 기준으로 다루기 위한 규칙이에요.

행동과 화면의 이름

‘결과 보기’는 행동, ‘설치 결과’는 도착 화면의 이름으로 구분했어요.

표시와 계산

사용자에게 보여주는 단위와 판정에 쓰는 단위가 섞이지 않도록 기준을 정했어요.

좁은 화면도 기본 조건

320px·390px에서 문장과 상태 전환을 함께 확인하는 기준을 두었어요.

05AI IN THE PROCESS

판단 기준을 먼저 정하고, 반복 확인에 AI를 활용했어요.

01

작업의 출발점

해결할 문제, 사용자 흐름, 바꿀 범위와 유지할 범위를 먼저 정했어요.

02

AI가 도운 범위

반복해서 확인할 내용을 작은 작업 단위로 나누고, 여러 화면과 상태를 비교하는 작업에 활용했어요.

03

직접 내린 판단

UX 정책과 완료 조건을 직접 정하고, 결과가 기준에 맞는지 검수했어요.

기존 프로젝트 기록의 Define → Design → Explore → Review 흐름을 재구성했어요. 사용 도구·실행 로그·시간 절감 수치는 아직 추가하지 않았어요.
