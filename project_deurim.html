01Overview

사기 전에, 이 자리에 들어가는지부터 답해요

냉장고는 규격표를 봐도 실제 자리에 들어갈지, 문을 열 수 있을지 알기 어려워요. 들임은 사용자가 잰 공간과 제조사가 공개한 설치 기준을 3D에서 함께 비교해, 설치할 수 있는지부터 알려줘요.

02Core Problem

숫자는 모두 있었지만, 답은 사용자가 계산해야 했어요

제품에는 본체 치수와 제조사 설치 기준이, 집에는 사용자가 잰 공간 치수가 있어요. 이 숫자들을 머릿속에서 공간으로 겹쳐 보면서 네 가지를 한꺼번에 판단해야 했어요.

그래서, 이렇게 봤어요

사용자에게 필요한 건 숫자 하나하나가 아니라 ‘이 공간에 설치할 수 있는가’에 대한 답이었어요.

03What I Saw

첫 화면은 계산을 검증하는 도구였어요

사용자보다 판정 엔진을 위한 화면이었어요. 제품 페이지에서 막 넘어온 사용자의 입장에서 실행 중인 화면을 다시 보며 세 가지를 물었고, 답은 모두 ‘아니요’⁠였어요.

  1. Q1

    무엇을 재야 하는지, 안내 없이 알 수 있나요?

    아니요

    숫자 칸 세 개와 긴 설명뿐이었어요. 줄자를 어디에 대야 하는지 보여주는 그림이 없었어요.

  2. Q2

    설치할 수 없을 때, 3D만 보고 어디가 부족한지 알 수 있나요?

    아니요

    3D는 통과한 여유 공간까지 늘 칠해 두는 뷰어였어요. 정작 문을 열 수 없다는 실패는 3D에 없었어요.

  3. Q3

    295mm, 1900mm 같은 기준을 몰라도 결과를 이해할 수 있나요?

    아니요

    결론은 설정과 시나리오 버튼을 모두 지난 곳, 제조사 수치부터 나열한 열 줄짜리 표 안에 있었어요.

사용자에게 필요한 건 열한 개의 설정이 아니라, 세 개의 치수와 하나의 답이었어요.

AI가 도운 일구현할 때마다 이 기준이 담긴 작업 규칙을 먼저 읽고 따랐어요.

직접 판단한 일점검 결과를 규칙으로 정했어요. 문제부터 말하고, 실패는 3D에도 보이고, 새 입력은 이유가 있을 때만 더해요.

04Design Decisions

보여줄 것보다, 사용자가 지금 판단할 것부터 정했어요

세 질문에 답하도록 결과의 순서, 3D의 역할, 묻는 방식을 각각 다시 설계했어요.

01결과

보고서 대신 답을 먼저, 모자란 만큼을 가장 크게 보여줬어요

문제
결론이 설정 아래 표에 있었고, 통과한 항목과 실패한 항목이 같은 무게로 나열됐어요.
관찰
‘필요 295mm, 확보 94mm’⁠는 계산으로는 정확하지만, 사용자에게 무엇을 바꿔야 하는지 알려주지 않았어요.
변경
한 줄의 답, 얼마나 더 필요한지, 무엇이 부족한지, 현재와 필요, 누구의 기준인지 순서로 바꾸고 통과한 항목은 목록에서 뺐어요.
결과
‘20.1cm 더 필요’⁠가 먼저 보여서, 읽자마자 무엇이 얼마나 모자란지 알 수 있어요.

After

AI가 도운 일엔진 용어가 사용자 화면에 새어 나오면 자동 검사가 실패하도록 만들었어요.

직접 판단한 일사용자에게 보이는 문구는 한 곳에서만 관리하고, 계산 용어는 화면에 쓰지 않기로 정했어요.

023D

3D는 모든 걸 칠하는 뷰어에서, 모자란 곳을 가리키는 도구가 됐어요

문제
3D가 통과한 여유 공간까지 늘 칠하고 있어서, 결과는 ‘설치 불가’⁠인데 화면은 괜찮아 보였어요.
관찰
숫자로 비교하기 어려운 건 제품과 공간의 관계예요. 결과와 다른 말을 하는 3D는 판단을 흐리게 했어요.
변경
통과한 곳은 그리지 않고, 모자란 곳만 실제 위치에 실제 크기로 그렸어요. 결과에서 문제를 누르면 카메라가 그쪽으로 돌아가요.
결과
결과 패널과 3D가 같은 곳에서 같은 숫자를 말해요. 정면에서는 보이지 않던 옆 틈도 한 번에 보여요.

처음 시점

‘왼쪽 문을 열 공간이 모자라요’⁠를 누르면

누른 뒤

  • 위치 조절냉장고를 끌어 옮기면 틈과 문 공간이 바로 다시 계산돼요.
  • 문 열기문은 3D에서 잡지 않고 슬라이더로 열어요. 3D 안에서는 ‘냉장고 옮기기’ 한 가지 동작만 남겼어요.
  • 같은 계산드래그와 슬라이더는 판정과 같은 계산을 써요. 보여주기만 하는 각도는 없어요.
  • 카메라카메라는 누를 때만 움직여요. 마우스를 올리는 것만으로는 시점이 바뀌지 않아요.

AI가 도운 일3D 라벨을 눌러도 카메라가 움직이지 않던 원인을 추적해, 라벨과 결과 행이 서로 다른 동작을 부르던 한 줄을 찾았어요.

직접 판단한 일3D와 결과 패널은 같은 동작을 해야 한다는 기준으로 수정 범위를 정하고, 실제 화면에서 다시 확인했어요.

03입력

이미 답이 있는 질문은 다시 묻지 않았어요

문제
치수를 모두 입력해도 ‘아직 확인이 필요해요’⁠에서 멈췄어요. 벽 질문이 이미 ‘있어요’⁠로 선택돼 보여서, 같은 버튼을 다시 눌러야 결과가 나왔어요.
관찰
버튼 표시만 고쳐서는 아무것도 바꾸지 않는 클릭이 그대로 남았어요. 문제는 표시가 아니라 질문 자체였어요.
변경
벽 여부를 질문 대신 기본값이 있는 설정으로 바꿨어요. 기본값은 양쪽 벽이 있는 보수적인 조건이고, 바꾸면 바로 다시 계산해요.
결과
너비와 높이만 알려주면 바로 확정된 답이 나와요. 묻는 치수는 처음과 같은 세 가지뿐이에요.

Before

  1. 너비 ⁠·⁠ 높이 ⁠·⁠ 깊이 입력
  2. ‘아직 확인이 필요해요’
  3. 이미 선택된 ‘있어요’ 다시 누르기 (없앤 단계)
  4. 결과

After

  1. 너비 ⁠·⁠ 높이 ⁠·⁠ 깊이 입력
  2. 바로 결과
  3. 벽 조건을 바꾸면 다시 계산

AI가 도운 일입력을 건드린 작업마다 한 글자씩 입력하기, 지우기, 붙여넣기를 실제 키 입력으로 다시 확인했어요.

직접 판단한 일입력 중인 글자와 확정된 값을 나누고, 빈 칸을 0으로 보지 않는다는 규칙을 정했어요.

05Data Reliability

확인할 수 없는 건 단정하지 않았어요

경첩 위치, 최대로 열리는 각도, 문을 여는 데 필요한 옆 공간은 제조사가 공개하지 않는 경우가 많아요. 이 값을 추정해 ‘설치 가능⁠·⁠불가’⁠를 말하면 답은 늘지만, 틀릴 수 있어요.

  1. 01

    공개된 기준이 있으면

    확정해서 답하고, 출처를 옆에 둬요

    ‘Samsung 공식 설치 기준으로 확인했어요’⁠와 제조사 공식 페이지 링크가 결과에 함께 보여요.

  2. 02

    공개되지 않은 값은

    추정해서 채우지 않아요

    설치 깊이 70cm와 본체 깊이 66.9cm의 차이를 ‘뒤쪽 여유 3.1cm’ 같은 기준으로 바꿔 쓰지 않았어요.

  3. 03

    문 구조를 알 수 없으면

    3D에서도 문을 열지 않아요

    문 조작을 만들지 않고, ‘3D에는 문을 닫은 모습만 표시했어요’⁠라고 적어요.

  4. 04

    확인하지 못한 게 있으면

    누가 해결할 수 있는지 말해요

    사용자가 알려주면 되는 것과 제조사가 공개하지 않은 것을 다른 문장으로 안내해요.

  5. 05

    공개된 값만으로 답이 나오면

    답을 미루지 않아요

    문이 어느 쪽으로 열리는지 몰라도, 양쪽 모두 충분하면 ‘설치할 수 있어요’⁠라고 말해요.

  1. Before

    After

    사용자에게 할 일이 남은 것처럼 읽히던 문장을 바꿨어요

    제조사가 공개하지 않은 정보는 사용자가 더 입력해도 채워지지 않아요. ‘아직 확인이 필요해요’⁠는 무언가를 더 해야 할 것처럼 읽혔어요.

결과를 더 많이 보여주는 것보다, 틀린 확신을 주지 않는 게 중요했어요.

AI가 도운 일새 제품을 추가할 때마다 공식 출처와 값마다의 근거를 함께 기록했어요.

직접 판단한 일제조사 사실을 만들지 않고, 공식 근거 없이 ‘확인 불가’⁠를 통과나 실패로 바꾸지 않는다는 규칙을 정했어요.

06Key Screens

제품을 고르고, 공간을 알려주고, 답을 확인하기까지

완성된 흐름을 사용자의 순서대로 따라가요. 화면마다 사용자가 무엇을 판단하게 했는지 적었어요.

01 / 05

제품 선택

확인할 냉장고를 골라요.

모델명을 몰라도 브랜드로 좁혀 볼 수 있게 목록 위에 브랜드 한 줄만 뒀어요. 필터는 목록을 좁힐 뿐, 제품은 사용자가 직접 골라요.

02 / 05

공간 입력

설치할 자리의 너비⁠·⁠높이⁠·⁠깊이를 알려줘요.

치수마다 어디를 재는지 그림을 붙이고, 이 단계에서 누를 주요 버튼은 ‘내 공간에서 확인하기’ 하나로 두었어요.

03 / 05

3D 확인

왼쪽에서 바꾸고, 가운데에서 보고, 오른쪽에서 답을 읽어요.

입력과 결과를 마주 보게 두고, 3D는 그 사이에서 모자란 곳만 가리켜요. 치수를 바꾸면 세 곳이 함께 바뀌어요.

04 / 05

설치 결과

설치할 수 있는지, 설치할 때 무엇을 챙길지 확인해요.

설치 안내는 설치할 수 있을 때만 보여줘요. 실패한 결과 아래에 설치 요령이 나오면 결론과 어긋나기 때문이에요.

05 / 05

제품 변경

같은 공간에 다른 냉장고를 대 봐요.

제품을 바꿔도 잰 공간과 벽, 배치는 그대로 둬요. 이전 제품의 문 각도와 선택한 문제는 비우고, 문 구조가 공개되지 않은 제품에는 문 조작을 보여주지 않아요.

왜 다르게 만들었는지

  1. 01

    3D가 절반을 지켜요

    아래 덱은 남은 화면의 절반을 넘지 않아요. 설명해야 할 3D가 조작 패널에 가려지지 않게 했어요.

  2. 02

    답은 한 곳에서만

    덱에서 판정 문장을 뺐어요. 3D가 모자란 곳을 그리고 ‘결과 보기’⁠가 설명해요. 좁은 화면에서 같은 답을 두 번 말하면 맞춰 볼 것만 늘어나요.

  3. 03

    보는 조작은 3D 위로

    ‘공간 조절’⁠과 시점 버튼은 3D 가장자리로 옮기고, 덱에는 배치 위치⁠·⁠문 여는 정도⁠·⁠결과 보기만 남겼어요.

  4. 04

    나란히 대신 차례로

    문 여는 정도를 문 선택, 각도, 슬라이더 순서로 쌓아 390px에서 슬라이더를 움직일 폭이 약 150px에서 350px로 넓어졌어요.

    After

    판정과 두 버튼이 겹치던 덱을, 조작만 남긴 덱으로 바꿨어요

    ‘공간 조절’⁠과 ‘결과 보기’⁠는 같은 무게의 두 버튼이었지만, 하나는 방금 읽은 답을 고치는 일이고 하나는 다음으로 가는 길이었어요.

의도가 실제 화면에서도 유지되는지 확인했어요

QA는 버그 목록이 아니라, 정한 우선순위가 실제 너비와 상태에서도 지켜지는지 보는 일이었어요. 대표적인 세 가지예요.

08AI Workflow

무엇을 바꾸면 안 되는지부터 정했어요

AI에게 무엇을 시킬지보다 이게 먼저였어요. 구현은 AI 에이전트와 함께 했고, 무엇을 만들지, 어디까지 바꿔도 되는지, 언제 끝난 것으로 볼지는 제가 정해 문서로 남겼어요. 에이전트는 작업 전에 그 문서를 먼저 읽었어요.

  1. 정하기직접

    1. 01문제 발견실제 화면에서 사용자가 막히는 지점을 찾아요.
    2. 02UX 방향무엇을 먼저 답할지, 어떤 상태를 둘지 정해요.
    3. 03기준 자료제조사 공식 자료와 공식 이미지, 로고 원본을 기준으로 삼아요.
    4. 04범위 정하기바꿀 것과 바꾸면 안 되는 것을 함께 적어요.

  2. 만들기AI

    1. 05AI 에이전트 구현정한 범위 안에서 화면과 3D, 기준 문서를 함께 고쳐요.

  3. 확인하기함께

    1. 06실제 화면 검토빌드 통과가 아니라 실제 화면으로 판단해요.
    2. 07부작용 확인다른 화면과 상태가 흔들리지 않았는지 봐요.
    3. 08원인 수정증상이 보인 곳이 아니라 원인을 고쳐요.
    4. 09QA여러 너비와 상태에서 다시 확인해요.

바꾸면 안 되는 것

  • 기능디자인 작업은 판정을 바꾸지 않아요스타일이나 문구를 고치는 작업이 판정 로직을 조용히 바꾸지 않게 했어요.
  • 데이터제조사 값을 추정하지 않아요공식 근거가 없는 값은 비워 두고 ‘확인 불가’⁠로 남겨요.
  • 상태제품을 바꿔도 공간은 그대로예요집에 대한 정보는 남기고, 제품에 딸린 상태만 비워요.
  • 반응형모바일 작업이 데스크톱을 흔들지 않아요임시 max-width 수정으로 풀지 않고, 데스크톱 동작은 그대로 둬요.
  • 원인증상보다 원인을 고쳐요공유된 원인이 있으면 한 화면만 덮는 임시 수정을 하지 않아요. 요청하지 않은 화면도 함께 바꾸지 않아요.
  • 완료끝은 실제 화면으로 판단해요빌드가 통과해도 화면은 증명되지 않아요. ‘고쳤다’⁠는 이전 보고도 근거로 보지 않아요.

AI로 빨라진 일, 그 덕분에 집중한 일

AI로 반복 속도가 빨라진 일

  • 화면과 상태별 구현을 여러 번 바꿔 보는 일
  • 데스크톱과 모바일, 여러 너비의 변형
  • 3D 장면과 카메라 동작 수정
  • 화면 전체의 용어와 문구 점검
  • 실제 입력으로 흐름을 다시 돌리는 회귀 확인

그래서 제가 집중한 일

  • 사용자가 지금 판단해야 하는 것이 무엇인지
  • 확인할 수 없는 정보를 어떻게 말할지
  • 어디까지 바꾸고, 언제 끝난 것으로 볼지

09Outcome

실제로 쓸 수 있는 서비스가 됐어요

제품 선택부터 설치 판단까지, 지금 deurim.co.kr에서 직접 써 볼 수 있어요.

  1. 01

    끝까지 이어지는 흐름

    제품 선택, 공간 입력, 3D 확인, 설치 결과, 제품 변경이 한 흐름으로 이어져요.

  2. 02

    공식 자료로만 판정

    3개 브랜드 18개 제품을 제조사 공식 자료로 등록했고, 공개되지 않은 값은 비워 둬요.

  3. 03

    두 가지 화면 구조

    같은 판정을 데스크톱과 모바일이 각자의 우선순위로 보여줘요.

  4. 04

    다시 와도 이어지는 확인

    새로고침하거나 다시 들어와도 잰 공간은 그대로예요. 문 각도나 시점처럼 보던 상태만 새로 시작해요.

다음 작업에 가져갈 기준

복잡한 기능을 더 많이 보여주는 것보다, 사용자가 지금 무엇을 판단해야 하는지 분명하게 만드는 게 중요했어요. AI는 그 판단을 대신하지 않았고, 분명해진 판단을 더 빠르게 실제 화면으로 만들어 줬어요.

이 프로젝트에서 보여준 역량

  1. 01판단의 순서를 설계해요무엇이 부족한지, 얼마나, 누구의 기준인지의 순서로 복잡한 조건을 정리해요.
  2. 02틀린 확신을 만들지 않아요확인할 수 없는 정보는 추정하지 않고, 누가 해결할 수 있는지까지 말해요.
  3. 03AI에게 기준을 먼저 줘요바꾸면 안 되는 것과 완료 조건을 정하고, 반복 구현과 검증은 AI와 나눠요.
