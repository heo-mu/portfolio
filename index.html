작동하는 구조를 먼저 설계합니다.

기능 간 관계와 사용자 흐름을 정리해 복잡한 서비스를 일관된 구조로 연결합니다.
디자인 시스템과 개발 제약을 함께 고려하며, 운영 효율까지 이어질 수 있도록 설계합니다.

01 / Identity

시각보다 흐름과 관계를 먼저 설계합니다.
단일 화면이 아닌, 반복 가능한 구조와 일관된 시스템을 만듭니다.

02 / Background

에이전시에서 근무하며 17개의 웹사이트를 구축했습니다.
퍼블리싱을 직접 수행하며 HTML, CSS, JavaScript 레벨의 구조를 이해했고,
이를 통해 화면보다 동작 방식과 구현 흐름을 함께 고려하는 기준을 갖게 되었습니다.

이후 스타트업에서는 문제 정의 단계부터 참여하며 서비스를 함께 설계했습니다.
기능 단위가 아닌 문제와 흐름 중심으로 접근했고,
불필요한 작업보다 구조적인 의사결정에 더 많은 시간을 투자해왔습니다.

개발자와는 화면이 아닌 구조와 로직을 기준으로 소통하며 작업합니다.

03 / Philosophy

그래픽 표현보다 구조를 우선합니다.
어떻게 보이는가보다, 왜 그렇게 설계되어야 하는가를 더 중요하게 생각합니다.
제품은 한 번 완성되는 결과물이 아니라 지속적으로 운영되는 시스템입니다.
그래서 화면보다 흐름과 관계, 그리고 확장 가능한 구조를 기준으로 설계합니다.
