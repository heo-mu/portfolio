HR ⁠·⁠ Groupware

사내 그룹웨어조직과 권한을 기준으로 정리한 HR 플랫폼

인사⁠·⁠근태⁠·⁠전자결재⁠·⁠권한 관리를 한곳에서 다루는 사내 그룹웨어예요. 역할에 따라 필요한 정보와 해야 할 일이 달라지는 업무를, 조직⁠·⁠권한 구조와 결재 상태를 기준으로 정리했어요.

01Context

역할마다 달라지는 정보와 처리 순서

인사, 근태, 전자결재, 권한 관리처럼 흩어진 사내 업무를 한 흐름으로 묶어야 했어요. 같은 업무라도 부서⁠·⁠직책⁠·⁠역할에 따라 필요한 메뉴와 데이터가 달라요.

  1. 문제 01

    조직과 접근 범위

    부서⁠·⁠직책⁠·⁠역할에 따라 접근할 메뉴와 데이터가 달라져요.

  2. 문제 02

    문서와 처리 상태

    전자결재는 작성뿐 아니라 승인⁠·⁠반려⁠·⁠이력까지 이어서 읽혀야 해요.

설계 관점

메뉴를 늘리기보다 조직⁠·⁠권한의 관계와 결재의 처리 순서를 먼저 정리해야 한다고 봤어요.

02Information Architecture

역할에 따라 나뉘는 정보와 업무

조직도⁠·⁠부서⁠·⁠직책⁠·⁠역할 권한을 기준으로 메뉴와 데이터 접근 범위를 나누고, 결재는 모든 역할의 공통 상태로 다뤘어요.

  1. 01

    사용자

    인사⁠·⁠근태⁠·⁠신청⁠·⁠요청과 결재 흐름을 처리해요.

  2. 02

    관리자

    조직⁠·⁠회원⁠·⁠권한과 근태 운영을 관리해요.

  3. 03

    공통 결재 상태

    기안 → 승인 또는 반려 → 이력 확인 순서로 읽어요.

03Design Decisions

권한과 결재 상태의 설계 기준

화면을 나누기 전에 누가 무엇을 볼 수 있고, 지금 어떤 처리를 해야 하는지부터 정했어요.

01

조직과 역할을 접근 기준으로

문제
사용자마다 쓰는 기능과 접근할 수 있는 정보가 달라요.
판단
화면을 나누기 전에 조직과 역할의 관계를 먼저 정의해야 한다고 봤어요.
설계
조직도⁠·⁠부서⁠·⁠직책⁠·⁠역할 권한을 기준으로 메뉴와 데이터 접근 범위를 구성했어요.

02

결재의 현재와 다음을 함께

문제
기안 작성 이후에도 승인⁠·⁠반려⁠·⁠이력 확인이 이어져요.
판단
문서 자체보다 현재 상태와 처리 순서를 빠르게 읽는 것이 중요했어요.
설계
결재 단계를 나누고, 현재 상태와 다음 처리 항목을 함께 확인하도록 설계했어요.

04Interaction & Design System

개발과 맞춘 인터랙션⁠·⁠컴포넌트 기준

모달, 스크롤, 토스트처럼 반복되는 동작의 규칙을 먼저 정해 디자인과 개발의 해석 차이를 줄였어요.

인터랙션 동작 기준

모달과 토스트의 위치, 드롭다운 동작, 페이지 이동과 스크롤 영역, 모달의 진입⁠·⁠종료 상태를 하나의 기준으로 정리했어요.

디자인 시스템

컬러⁠·⁠타이포그래피 기준과 재사용 컴포넌트로 반복되는 화면 구조를 맞췄어요.

05Key Screens

사용자와 관리자의 업무 화면

사용자는 인사⁠·⁠근태⁠·⁠결재처럼 반복하는 일을 적은 단계로 처리하고, 관리자는 조직⁠·⁠사용자⁠·⁠권한⁠·⁠근태 데이터를 한곳에서 관리해요.

사용자

관리자

06Result

역할과 상태로 읽히는 업무 구조

흩어진 사내 업무를 역할과 상태 기준으로 다시 묶은 결과예요.

  1. 01

    권한별 접근 범위

    조직⁠·⁠직책⁠·⁠역할에 따라 메뉴와 데이터 접근 범위가 나뉘어요.

  2. 02

    상태로 읽히는 결재

    기안 → 승인⁠·⁠반려 → 이력으로 현재 상태와 다음 처리 항목을 확인해요.

  3. 03

    통일된 인터랙션 기준

    모달⁠·⁠토스트⁠·⁠스크롤 동작을 디자인과 개발이 같은 기준으로 구현했어요.

다음 작업에 가져갈 기준

기능을 모으는 것보다 역할과 처리 상태를 먼저 정리해야 업무 흐름이 읽혀요. 권한이 복잡한 제품에서는 화면보다 접근 구조를 먼저 정하는 순서를 기준으로 삼아요.

이 프로젝트에서 보여준 역량

  1. 01권한 기반 정보 구조조직⁠·⁠역할에 맞게 정보와 접근 범위를 나눴어요.
  2. 02업무 상태 설계현재 처리 상태와 다음 행동을 연결했어요.
  3. 03협업을 위한 동작 규칙컴포넌트와 전환 기준을 개발과 같은 기준으로 정리했어요.
